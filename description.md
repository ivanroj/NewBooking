Краткое описание проекта

Информационная система представляет собой Telegram Mini App для организации работы вузовских коворкингов. Приложение поддерживает работу с несколькими помещениями. Администратор системы может создавать новые коворкинг-пространства, настраивать их схемы и управлять рабочими местами. Студенты, используя интуитивно понятный интерфейс внутри Telegram, выбирают интересующее их помещение, просматривают актуальную схему занятости и бронируют свободные места. Для предотвращения злоупотреблений встроена система лимитов на количество активных броней. Главная цель — автоматизировать учет мест, исключить накладки в расписании и предоставить пользователям удобный, готовый к использованию продукт.
1. Пользователь:
Студент или сотрудник вуза, который регистрируется и авторизуется в системе, просматривает схему коворкинга, выбирает свободные места на нужные дату и время, создает и отменяет собственные бронирования, а также просматривает историю своих посещений.
2. Администратор:
Сотрудник, ответственный за сопровождение системы. Управляет местами и их параметрами, просматривает и изменяет любые бронирования, устанавливает лимиты бронирований на пользователя, контролирует актуальность схемы коворкинга и формирует отчеты по загрузке мест.

Технологический стек

    Backend: Язык программирования Go (версия 1.25+), REST API.

    Frontend (Telegram Mini App): Нативный стек интернета — HTML, CSS, JavaScript (интеграция с Telegram Web Apps API).

    База данных: PostgreSQL.

    Отрисовка схем: Использование Canvas или SVG для генерации и взаимодействия с планами помещений.

    Контроль качества и инфраструктура: GitHub (репозиторий и CI/CD), golangci-lint для бекенда, ESLint/Prettier для фронтенда.

    Тестирование: Автотесты (стандартный пакет testing для Go, Jest или аналоги для JS).

    Уведомления и задачи: Рассылка уведомлений (встроенная в Telegram или email) и фоновые процессы для снятия просроченных броней.

    Окружение: Сборка и деплой на серверах Linux (Docker).

Общие инструкции для ИИ-разработчика

При реализации каждого этапа необходимо строго соблюдать следующие правила:

    Чистота кода: Использовать линтеры (golangci-lint для Go, ESLint для JS). Перед завершением каждого этапа ИИ должен самостоятельно генерировать конфигурации линтеров, "прогонять" через них написанный код и исправлять все найденные предупреждения.

    Автотестирование: Никакого ручного тестирования. Каждый реализованный эндпоинт API и ключевой элемент бизнес-логики должен покрываться unit- и интеграционными автотестами. ИИ должен писать тесты и предоставлять команды для их успешного прогона.

    Версионирование: Все изменения должны фиксироваться в GitHub-репозитории с осмысленными коммитами по завершении логических блоков.

План реализации (по этапам)

Этап 1: Проектирование БД, архитектуры и инициализация GitHub

    Инициализация репозитория на GitHub, создание структуры проекта (Go для бекенда, статика/сборщик для фронтенда).

    Настройка базовых конфигураций golangci-lint и ESLint. Создание CI-пайплайна (GitHub Actions) для автоматического запуска линтеров и тестов при пуше.

    Настройка взаимодействия с Telegram Web Apps API.

    Проектирование схемы БД в PostgreSQL. Добавление сущности Room (помещение коворкинга). Основные таблицы: Room, Workspace, User, Booking, BookingSettings.

    Написание SQL-миграций и базовых тестов на подключение к БД.

Этап 2: Разработка Backend — Авторизация и Ролевая модель

    Реализация логики для роли "Студент": методы регистрации и авторизации.

    Реализация логики для роли "Администратор". Внедрение миграции для создания стандартной учетной записи администратора.

    Создание API для получения списка помещений.

    Требование: Покрытие разработанных API-методов интеграционными автотестами (проверка успешной авторизации, проверка отказа при неверных данных). Прогон golangci-lint.

Этап 3: Разработка Backend — Управление помещениями и Бронирование

    Разработка CRUD-операций для создания/удаления помещений и редактирования рабочих мест (UC-5).

    Реализация ядра бронирования (UC-2): транзакционная проверка доступности места, валидация лимитов студента.

    Разработка API для отмены броней пользователем (UC-3) и администратором (UC-6), а также настройки лимитов (UC-7).

    Требование: Написание unit-тестов для алгоритма проверки пересечений бронирований и лимитов. Запуск тестов и линтера для валидации этапа.

Этап 4: Разработка Frontend — Клиентская часть (Студент)

    Разработка страниц регистрации и входа для студента.

    Создание чистого, "продового" интерфейса Telegram Mini App. Интерфейс должен быть свободен от отладочной и избыточной технической информации, выглядеть готовым продуктом для конечного пользователя.

    Реализация экранов: Выбор коворкинга ➔ Просмотр схемы помещения ➔ Бронирование места.

    Создание раздела просмотра истории бронирований (UC-4).

    Требование: Написание базовых автотестов для фронтенда (проверка рендера ключевых компонентов и валидации форм). Проверка кода через ESLint.

Этап 5: Разработка Frontend — Панель Администратора и Интерактивные схемы

    Разработка интерфейса авторизации для администратора.

    Создание интерфейса добавления новых коворкингов и визуального редактора (Canvas/SVG) для расстановки мест на плане.

    Разработка интерфейса просмотра бронирований и управления ими.

    Внедрение модуля статистики и отчетов (UC-8).

    Требование: Проверка всех новых JS-скриптов линтером и написание тестов для функций трансформации данных аналитики.

Этап 6: Уведомления и Фоновые процессы

    Настройка сервиса отправки уведомлений через Telegram-бота (интеграция API).

    Реализация фоновых worker-ов на Go для автоматического обновления статусов (например, снятие неактуальных броней).

    Требование: Написание тестов для логики worker-ов (mock-тестирование без реальной отправки сообщений). Прогон всех тестов бэкенда.

Этап 7: Подготовка к релизу и Развертывание

    Написание Dockerfile и docker-compose.yml для поднятия базы данных, бекенда и веб-сервера (nginx) для раздачи статики TMA.

    Финальный прогон всего набора автотестов (backend + frontend) и проверка CI/CD пайплайна в GitHub.

    Инструкции по деплою готового решения на целевой Linux-сервер.
